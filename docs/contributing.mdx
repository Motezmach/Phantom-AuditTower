# Contributing

Phantom is maintained in the 3S GitLab repository. Keep changes focused and preserve the working scan, sandbox, viewer, and reporting paths.

## Setup

```bash
git clone https://gitlab.3s.com.tn/internships/audit-tower.git
cd audit-tower
uv sync
```

PowerShell and Bash use the same clone/install commands. Go is only needed when changing or packaging the TUI sidecar. Docker is needed for sandbox-backed scans.

## Local checks

```bash
uv run pytest -q
git diff --check
```

Build the sandbox with:

```bash
docker build -f containers/Dockerfile -t phantom-sandbox:1.3.0 .
```

The viewer source is in `phantom/interface/viewer/frontend/`. If it changes:

```bash
cd phantom/interface/viewer/frontend
npm ci
npm run build
```

Commit the regenerated bundle under `phantom/interface/viewer/static/`.

## Skills and agent types

Skills live under `phantom/skills/`. A good skill states its scope, workflow, evidence requirements, validation method, false-positive limits, and reporting guidance.

Specialized agent types are registered in `phantom/agents/factory.py` and receive prompts from `phantom/agents/prompts/`.

## Merge request checklist

- Tests pass, or the failure is explained.
- `git diff --check` is clean.
- No API keys, credentials, private targets, generated `phantom_runs/`, virtual environments, or build caches are staged.
- Documentation matches the public `phantom` command and `PHANTOM_*` configuration.
- The merge request explains the behavior change and verification performed.
